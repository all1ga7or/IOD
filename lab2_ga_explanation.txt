================================================================================
 ЛАБОРАТОРНА РОБОТА №2 — ЗАВДАННЯ 9
 Генетичний алгоритм (GA) для розв'язання задачі ранжування
================================================================================

ГЕНЕТИЧНИЙ АЛГОРИТМ (Genetic Algorithm, GA) — еволюційний метод оптимізації,
натхненний біологічною еволюцією (відбір, схрещування, мутація).
Він найкращим чином підходить для задач ранжування, оскільки:
— працює з перестановками (хромосома = послідовність об'єктів);
— ефективно комбінує часткові рішення через оператор PMX;
— зберігає популяцію кандидатів, а не один єдиний розв'язок.

================================================================================
 КРОК 1: ПОСТАНОВКА ЗАДАЧІ
================================================================================

Задача:
Маємо N об'єктів (серіалів) після евристичного відсіювання та M експертів.
На цьому етапі кожен експерт оцінює вже не ТОП-3, а надає ПОВНЕ РАНЖУВАННЯ 
для всієї залишеної множини N об'єктів. (Для алгоритму ми генеруємо ці повні
перестановки рандомно).
Потрібно знайти таку послідовність (ранжування) усіх N об'єктів,
яка максимально узгоджується з цими повними ранжуваннями всіх експертів одночасно.

================================================================================
 КРОК 2: ПОБУДОВА МАТРИЦІ ПЕРЕВАГ (Preference Matrix)
================================================================================

Матриця переваг P[i][j] показує, скільки експертів вважають,
що об'єкт i кращий за об'єкт j.

Правила заповнення:
Оскільки кожен експерт дав повне ранжування об'єктів, ми просто беремо
кожні 2 об'єкти (i та j) з його списку:
1) Якщо у списку експерта об'єкт A стоїть вище (краще) за об'єкт B,
   то P[A][B] += 1 (одна людина вважає A кращим за B).

Приклад для 4 об'єктів (A, B, C, D) та 3 експертів:

Ек1: 1-A, 2-B, 3-C, 4-D  → A>B, A>C, A>D, B>C, B>D, C>D
Ек2: 1-B, 2-D, 3-C, 4-A  → B>D, B>C, B>A, D>C, D>A, C>A
Ек3: 1-A, 2-D, 3-B, 4-C  → A>D, A>B, A>C, D>B, D>C, B>C

Результуюча матриця P:
       A    B    C    D
  A  [ 0    2    3    3 ]     A>B: 2 рази (Ек1, Ек3)
  B  [ 1    0    2    2 ]     B>A: 1 раз  (Ек2)
  C  [ 1    1    0    1 ]     ...
  D  [ 0    1    0    0 ]

================================================================================
 КРОК 3: ФІТНЕС-ФУНКЦІЯ (Fitness Function)
================================================================================

Фітнес-функція визначає "якість" конкретної перестановки.
Формула:
                    n-1   n
  f(π) =  Σ    Σ   P[π(i)][π(j)]
                   i=1  j=i+1

Тобто ми беремо всі пари об'єктів у нашому списку, де лівий стоїть раніше
за правого, і додаємо відповідний елемент із матриці переваг.
Чим більше пар "узгоджені" з думками експертів, тим вищий бал.

Приклад:
  Перестановка π = [A, B, C, D]

  Пари:       P[π(i)][π(j)]
  (A, B)  →   P[A][B] = 2
  (A, C)  →   P[A][C] = 3
  (A, D)  →   P[A][D] = 3
  (B, C)  →   P[B][C] = 2
  (B, D)  →   P[B][D] = 2
  (C, D)  →   P[C][D] = 1
  ─────────────────────────
  Fitness  =  2+3+3+2+2+1 = 13

  Перестановка π = [D, C, B, A]

  Пари:       P[π(i)][π(j)]
  (D, C)  →   P[D][C] = 0
  (D, B)  →   P[D][B] = 1
  (D, A)  →   P[D][A] = 0
  (C, B)  →   P[C][B] = 1
  (C, A)  →   P[C][A] = 1
  (B, A)  →   P[B][A] = 1
  ─────────────────────────
  Fitness  =  0+1+0+1+1+1 = 4

Висновок: [A,B,C,D] з балом 13 набагато краще ніж [D,C,B,A] з балом 4.

================================================================================
 КРОК 4: ІНІЦІАЛІЗАЦІЯ ПОПУЛЯЦІЇ
================================================================================

Створюємо початкову популяцію з 50 випадкових перестановок.
Кожна перестановка — це "особина" (хромосома).

Параметри GA:
  — Розмір популяції (popSize): 50
  — Кількість поколінь (generations): 200
  — Ймовірність мутації (mutationRate): 15%

Приклад початкової популяції (фрагмент):
  Хромосома  1: [C, A, D, B]  → Fitness = ?
  Хромосома  2: [B, D, A, C]  → Fitness = ?
  ...
  Хромосома 50: [A, B, C, D]  → Fitness = ?

================================================================================
 КРОК 5: ЦИКЛ ЕВОЛЮЦІЇ (Головний цикл GA)
================================================================================

Повторюємо 200 разів (поколінь):

 5.1. ОЦІНКА
     Рахуємо фітнес для кожної хромосоми в популяції.
     Сортуємо від найкращої до найгіршої.

 5.2. СЕЛЕКЦІЯ (Відбір)
     Стратегія: Top-50% (елітизм).
     Залишаємо 25 найкращих хромосом як "батьків".
     Інші 25 гірших — відкидаємо.

 5.3. СХРЕЩУВАННЯ (PMX — Partially Matched Crossover)
     Беремо двох випадкових батьків і створюємо нащадка.

     Приклад PMX:
     Батько 1:  [A, |B, C|, D]     (обрано ділянку B,C)
     Батько 2:  [D, |A, B|, C]

     Крок 1: Копіюємо ділянку Батька 1 у нащадка:
       Нащадок:   [_, |B, C|, _]    (B і C — зайняті)

     Крок 2: Заповнюємо решту позицій з Батька 2 (пропускаючи вже зайняті):
       Батько 2 = [D, A, B, C] → пропускаємо B, C → беремо D, A
       Нащадок:   [D, |B, C|, A]

     Результат: Нащадок = [D, B, C, A]
     (Нащадок "успадкував" ділянку [B,C] від Батька 1 і решту від Батька 2.)

 5.4. МУТАЦІЯ (Swap)
     З ймовірністю 15% випадково міняємо місцями 2 гени в нащадку.

     Приклад:
       До мутації:    [D, B, C, A]
       Swap(1, 3):    [D, A, C, B]  ← поміняли B та A місцями

     Мутація потрібна, щоб "струсити" популяцію та уникнути застрягання
     в локальних оптимумах (подібно до біологічних мутацій в ДНК).

 5.5. ФОРМУВАННЯ НОВОГО ПОКОЛІННЯ
     Нова популяція = 25 батьків (топ) + 25 нових нащадків = 50 особин.
     Повертаємося до кроку 5.1.

================================================================================
 КРОК 6: РЕЗУЛЬТАТ (Після 200 поколінь)
================================================================================

Алгоритм зберігає найкращу хромосому, яку коли-небудь бачив.
Це і є наше ФІНАЛЬНЕ КОМПРОМІСНЕ РАНЖУВАННЯ.

Приклад результату:
  Покоління   0: Найкращий фітнес = 8
  Покоління  20: Найкращий фітнес = 11
  Покоління  40: Найкращий фітнес = 13
  Покоління  60: Найкращий фітнес = 13    ← алгоритм збігся (конвергенція)
  ...
  Покоління 200: Найкращий фітнес = 13

  Фінальне ранжування: [A, B, C, D]
  Це означає, що послідовність A→B→C→D максимально узгоджується
  з голосами всіх трьох експертів.

================================================================================
 ЧОМУ САМЕ ГЕНЕТИЧНИЙ АЛГОРИТМ?
================================================================================

Порівняння з іншими еволюційними алгоритмами:

┌──────────────────────┬───────────────────────────────────────────────────┐
│ Алгоритм             │ Особливості для задачі ранжування                │
├──────────────────────┼───────────────────────────────────────────────────┤
│ Генетичний (GA)      │ ✅ PMX-схрещування зберігає структуру перестановок│
│                      │ ✅ Популяція забезпечує різноманітність пошуку    │
│                      │ ✅ Елітизм гарантує збереження найкращих рішень   │
├──────────────────────┼───────────────────────────────────────────────────┤
│ Імітація відпалу (SA)│ ⚠️ Один розв'язок, ризик локального мінімуму     │
│                      │ ⚠️ Потрібно ретельно підбирати розклад охолод.   │
├──────────────────────┼───────────────────────────────────────────────────┤
│ Мурашиний (ACO)      │ ⚠️ Феромони не мають природної інтерпретації     │
│                      │    для задачі ранжування (немає "відстаней")      │
├──────────────────────┼───────────────────────────────────────────────────┤
│ Бджолиний (ABC)      │ ⚠️ Ефективний для неперервних просторів,         │
│                      │    менш природний для перестановок                │
└──────────────────────┴───────────────────────────────────────────────────┘

Висновок: GA є найприроднішим вибором для задач ранжування, бо:
1. Хромосома = перестановка (пряме кодування рішення).
2. PMX-оператор гарантує, що нащадок — завжди коректна перестановка.
3. Популяційний підхід дає кращу розвідку простору рішень.

================================================================================
 РЕАЛІЗАЦІЯ В КОДІ (lib/db.js, рядки 180–306)
================================================================================

Функція: runGeneticAlgorithmLab2(objects, votes, options)

  Вхід:
    — objects: масив об'єктів (після евристичної фільтрації)
    — votes: масив голосів експертів [{picks: [{objectId, rank}]}]
    — options: {popSize: 50, generations: 200, mutationRate: 0.15}

  Вихід:
    — ranking: фінальний список [{rank, id, name, total_score}]
    — log: журнал збіжності [{generation, bestFitness}]
    — bestFitness: найкращий досягнутий бал

  Алгоритм:
    1. Побудувати матрицю переваг P[i][j] з голосів.
    2. Створити 50 випадкових перестановок (популяцію).
    3. Повторити 200 разів:
       a) Оцінити fitness кожної хромосоми.
       b) Відібрати Топ-50% (селекція).
       c) Створити нащадків через PMX (схрещування).
       d) Застосувати swap-мутацію з ймовірністю 15%.
    4. Повернути найкращу хромосому як фінальне ранжування.
