ЗВІТ З ЛАБОРАТОРНОЇ РОБОТИ №8
Тема: Визначення максимального прискорення систем за допомогою законів Амдала

Мета роботи: Навчитися розраховувати потенційне прискорення багатопроцесорних систем, аналізувати вплив послідовної частки коду на ефективність паралелізму та виявляти логічні несумісності в параметрах системи.

Варіант №15
Вихідні дані (Таблиця 2):
- Частка паралельних обчислень (1 - β): 0.65
- Задане прискорення для системи (S): 14
- Цільовий діапазон прискорення: від 65% до 90% від граничного (Smax)

---

1. ТЕОРЕТИЧНІ РОЗРАХУНКИ

Спершу визначимо частку послідовних обчислень (β):
β = 1 - (1 - β) = 1 - 0.65 = 0.35

Визначимо максимально можливе (граничне) прискорення згідно з 1-м законом Амдала:
Smax = 1 / β = 1 / 0.35 ≈ 2.857

Тепер спробуємо розрахувати кількість процесорів (l), необхідну для досягнення заданого прискорення S=14. Використовуємо формулу:
S = l / (l*β + 1 - β)
14 = l / (l*0.35 + 0.65)
14 * (0.35l + 0.65) = l
4.9l + 9.1 = l
3.9l = -9.1
l ≈ -2.33

Як бачимо, результат від'ємний, що фізично неможливо.

---

2. АНАЛІЗ НЕСУМІСНОСТІ

У ході розрахунків було виявлено серйозну несумісність між часткою паралельних обчислень та бажаним прискоренням.
Причина: Задане прискорення (14) перевищує теоретичний ліміт системи (Smax = 2.857). Навіть при нескінченній кількості процесорів система з 35% послідовного коду не може прискоритися більш ніж у 2.857 раза.

---

3. ПРОПОНОВАНИЙ СУМІСНИЙ ВАРІАНТ

Для того, щоб система функціонувала адекватно, і прискорення 14 було досяжним, необхідно значно зменшити частку послідовного коду.
Запропоноване значення (1 - β) = 0.95 (тобто лише 5% коду є послідовним).

Нові розрахунки:
β = 0.05
Smax = 1 / 0.05 = 20
Тепер S=14 є досяжним. Знайдемо кількість процесорів l:
14 = l / (0.05l + 0.95)
14 * (0.05l + 0.95) = l
0.7l + 13.3 = l
0.3l = 13.3
l = 44.33 => приймаємо l = 45 процесорів.

Знайдемо кількість процесорів для забезпечення цільового діапазону (65%-90% від Smax):
Нижня межа (65% * 20 = 13):
13 = l / (0.05l + 0.95) => 0.65l + 12.35 = l => 0.35l = 12.35 => l ≈ 35.28 => l = 36
Верхня межа (90% * 20 = 18):
18 = l / (0.05l + 0.95) => 0.9l + 17.1 = l => 0.1l = 17.1 => l = 171

5. ОПИС ТА АРХІТЕКТУРА ПРОГРАМНОЇ РЕАЛІЗАЦІЇ

На відміну від попередніх консольних рішень, для розв'язання цієї задачі було інтегровано повноцінний інтерактивний модуль у загальний сучасний вебдодаток на базі фреймворку Next.js та бібліотеки React.

Ключові аспекти реалізації:
- Модульна архітектура: Компонент для 8-ї лабораторної успішно ізольовано у власному маршруті (/lab8), що забезпечує легку інтеграцію в екосистему проєкту.
- Реактивний Data Binding: Всі вхідні дані (Частка паралельних обчислень, S, a1 та a2) обробляються через React State, а результати миттєво перераховуються хуком useMemo без перезавантаження сторінки.
- Валідація форм: Впроваджено строгу перевірку граничних значень (наприклад, a1 та a2 фізично обмежені межами від 0.01 до 0.99). Якщо користувач введе некоректні дані, додаток повідомить його м'якими візуальними попередженнями (червоні межі та текст).
- Генерація SVG-документів на льоту: Головною "родзинкою" рішення є інтерактивний графік, який в реальному часі малює нелінійну криву закону Амдала за допомогою SVG. На ній одразу позначаються асимптота Smax та точні розраховані точки кількості процесорів для вимог задачі. 

ВИСНОВКИ ТА АНАЛІЗ
Під час виконання лабораторної роботи на практиці розібрано зворотний бік закону Амдала. Ми переконалися, що збільшення кількості процесорних ядер є ефективним рішенням лише до певної межі.
Наочно продемонстровано сутність обмеження Smax: жодне кількісне розширення апаратної бази не здатне вивести прискорення алгоритму за цю межу, що генерується неподільним послідовним кодом системи. Саме тому у Варіанті 15 була виявлена концептуальна несумісність — система фізично неспроможна досягти прискорення S=14 з такою низькою часткою розпаралелення (відповідні повідомлення та перерахунки успішно опрацьовує вебдодаток). Для реалізації високих запитів прискорення єдиним вірним кроком залишається фундаментальна зміна самого алгоритму (зменшення β).
